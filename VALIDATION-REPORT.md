## Fixes applied

- Removed the native WebView's `showOffline()` replacement page. Main-frame network failures now emit an offline event and leave the app document in place so the service worker can provide its cached shell.
- Removed the legacy `public/offline.html` page and its Vercel header rule.
- Bumped the service-worker cache version; navigation now falls back to the cached requested route or cached root when the network fails or returns an unsuccessful response. Static assets fall back to their cached copy when the network response fails.

## Important release verification still required

This is source-level validation, not a signed Android release test. A full Vite/TypeScript production build, Gradle APK/AAB build, and physical-device tests are still required to validate runtime behavior. In particular:

1. Load WyBuild successfully online once so the service worker can cache the app shell and bundles.
2. Force-stop/reopen in airplane mode; confirm the cached interface opens and the offline toast appears without a standalone offline page.
3. Restore validated internet; confirm the online toast appears.
4. Test Contacts on an Android device: select a contact, cancel, and select a contact without a phone number.
5. Confirm denied permissions and unsupported hardware are handled without crashing.

Offline startup cannot be guaranteed before the app has ever loaded online and cached its resources. Login, billing, cloud builds, and server-backed operations still need internet; offline caching preserves the app shell, not remote server availability.


## Native offline limitation

The service worker is deliberately disabled in Capacitor. The app shell is bundled, but API calls, GitHub operations, payments and other server-backed actions require network access. On native startup a server outage is represented as an unreachable-backend state rather than silently signing the user out.

## v51 repository-secret fallback (2026-10-24)

The Vercel environment resolver now uses this precedence independently for API base URL and Google web client ID: non-empty Vercel Production value → matching GitHub repository Actions secret → matching GitHub repository variable → existing project configuration fallback. This also works when `VERCEL_TOKEN` is absent. Supported API secret names are `NEXT_PUBLIC_API_BASE_URL`, `VITE_API_BASE_URL`, and `API_BASE_URL`; supported Google client secret names are `NEXT_PUBLIC_GOOGLE_WEB_CLIENT_ID`, `VITE_GOOGLE_WEB_CLIENT_ID`, and `GOOGLE_WEB_CLIENT_ID`.
